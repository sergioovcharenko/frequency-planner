# Каталог моделей ретрансляторів — дизайн

## Мета

Додати до Frequency Planner окремий блок вибору ретранслятора. Планувальник має відрізняти приймальні діапазони від передавальних і не позначати штатний приймальний канал як джерело завади.

## Межі першої версії

Перша версія містить дві моделі з відкритими характеристиками та режим «Інша модель»:

1. **Tactical Technology — Repeater on Mavic**
   - діапазони керування: 433–520, 720–1020 та 2100–2700 МГц;
   - приймання відео від FPV: номінальні діапазони 5.8, 6.5 та 7.5 ГГц;
   - передавання відео на землю: номінальні діапазони 1.2 та 3.3 ГГц;
   - джерело: https://www.tactech.world/en/products/communication-and-control/repeater
2. **BlueBird Tech — Віщун-5.8**
   - приймання відео: 4990–5945 МГц;
   - передавання відео оператору: 1.2/1.3 ГГц, 9 каналів;
   - керування: опційний ELRS/TBS/LoRa-модуль, точний діапазон залежить від комплектації;
   - джерело: https://www.blue-bird.tech/en/products/wireless-retranslator-blue-bird-repeater/
3. **Інша модель**
   - користувач задає назву;
   - користувач додає приймальні й передавальні частоти або діапазони вручну.

Цифри з маркетингових сторінок зберігаються разом із URL джерела. Якщо джерело дає лише назву діапазону (наприклад, 5.8 ГГц), застосунок не вигадує ширину каналу і показує обмежену точність.

## Інтерфейс

Новий блок «Ретранслятор» розташовується між діапазонами керування і матрицею відеоканалів.

Блок містить:

- випадаючий список моделі;
- картку характеристик із посиланням на джерело;
- окремі рядки «Приймання від FPV», «Передавання на землю» і «Керування FPV»;
- вибір доступного варіанта, якщо модель підтримує кілька діапазонів;
- статус повноти даних;
- кнопку «Змінити», підтвердження, «Зберегти» та «Скасувати» за тим самим принципом, що й наявні налаштування;
- для «Інша модель» — додавання та видалення довільних RX/TX-діапазонів.

Налаштування ретранслятора заблоковані після відкриття сторінки. Зміни зберігаються локально на пристрої разом з основним профілем. «Відновити штатні» повертає ретранслятор у стан «Не вибрано».

## Модель даних

Профіль отримує поле `repeater`:

```js
{
  modelId: null,
  customName: '',
  selections: {
    videoRx: null,
    videoTx: null,
    controlTx: null
  },
  customRanges: []
}
```

Каталог моделей зберігається окремо від користувацького профілю. Кожен радіоканал має напрямок (`rx` або `tx`), призначення (`video` або `control`), числовий інтервал за наявності, текстове позначення та URL джерела.

## Правила перевірки

1. **Сумісність відеоприймання.** Відеоканал борта сумісний, якщо він входить до точного RX-діапазону ретранслятора. Якщо відома лише номінальна смуга, результат — «Потрібне уточнення».
2. **Прямий конфлікт.** Для оцінки завад використовуються лише TX-канали ретранслятора. RX-діапазон не вважається джерелом випромінювання.
3. **Відстань між частотами.** Наявні пороги зберігаються: до 10 МГц — «Небезпечно», 11–27 МГц — «Обережно».
4. **Гармоніки.** Передавальні частоти ретранслятора порівнюються з відеоканалами й діапазонами керування. Результат формулюється як математично можлива, а не підтверджена завада.
5. **Неповні дані.** Відсутні характеристики ніколи не дають статус «Підходить»; застосунок показує «Не перевірено» або «Потрібне уточнення» і називає відсутній параметр.
6. **Рекомендації.** Рейтинг відеоканалів враховує сумісність із RX ретранслятора, ризики від його TX та наявні правила для керування.

## Повідомлення та помилки

- Якщо для моделі не вибрано необхідний діапазон, застосунок просить зробити вибір.
- Якщо ручний діапазон має початок, більший або рівний кінцю, збереження блокується.
- Якщо введено нечислове або від’ємне значення, збереження блокується.
- Якщо даних виробника недостатньо, це відображається біля конкретного параметра, а не маскується загальним зеленим статусом.
- Посилання на джерело завжди видиме у картці моделі.

## Тестування

Автоматичні тести мають перевіряти:

- структуру та унікальність моделей каталогу;
- розділення RX і TX у розрахунках;
- сумісність штатних дев’яти каналів із точним RX-діапазоном;
- статус «Потрібне уточнення» для номінальних смуг без меж;
- конфлікти й гармоніки лише від TX;
- валідацію ручних діапазонів;
- збереження, відновлення та міграцію старого локального профілю без поля `repeater`;
- блокування редагування та підтвердження в інтерфейсі.

## Критерії готовності

- користувач може вибрати одну з двох моделей або ручний режим;
- характеристики та джерело моделі відображаються в інтерфейсі;
- приймальні діапазони не створюють хибних повідомлень про заваду;
- результати пояснюють, що сумісне, що конфліктує і яких даних бракує;
- наявні налаштування користувачів не втрачаються;
- усі старі й нові тести проходять;
- оновлення автоматично публікується на чинній GitHub Pages-адресі.
